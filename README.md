技术本身我是真喜欢，但广告这行更让我上心的，是它前面那截：谁在买、谁在卖、一次曝光怎么在几十毫秒里成交，钱又沿着哪条路分回去。工程只是这条因果链的中段，只盯着中段，很多决定会看不出道理。

我的日常是 DSP 竞价。一个 OpenRTB 请求进来，出价出去，中间卡着一个不讲情面的 `tmax`。往上是协议、拍卖规则、SDK 与合规，链路上是定向、频控、pacing 和打分，再往后是 Kafka、Flink 和在线推理。

遇到自己还没吃透的环节，我习惯把它拆开重写一遍，直到能完整讲给别人听。这也给了我一把尺子：业务上的说法和工程上的延迟预算要是对不上，多半是我还有地方没想透。这些年写下来的都整理到了 **[cylshao.com](https://cylshao.com)**，到现在大约 160 篇。

## 最近在看：AI Agent

今年我把更多时间放在了 AI Agent 上。差别不在模型聪不聪明：聊天能给你一份步骤，却一步都不会替你做；要真把事办完，它得自己调工具、把中间状态保住，在需要人点头的地方停下来。

对企业来说，值钱的正是这一段。过去的自动化只覆盖规则清晰、量又大的环节，剩下那些「说得清、却写不成规则」的活——查数、核对、跨几个系统来回搬——一直得有人盯着。放到广告业务里就很具体：运营不必再排队等取数，投放出现异常时也能先让 Agent 把指标拉齐、给出初步判断，人只在该下判断的地方出现。

市场这一年已经从热闹回到务实，愿意先付钱的基本都是边界清楚、结果可核对的场景。所以我不太看重换哪个模型，能力上限更多取决于企业自己的数据、流程和权限梳理到什么程度，而这恰恰是模型替不掉的部分。

往前看，Agent 大概不会是一个独立产品，而会沉成业务系统里的一层，门槛也从「会不会用模型」挪到「敢把系统交给它到什么程度」。这件事我会持续做下去：在广告业务里找值得交出去的环节落地，把想清楚的和踩过的坑写下来。

## 在写什么

上面这些最后大都落成了文章。四个方向，问的其实是同一件事：流量怎么变成收入，系统在中间怎么跑。

| 方向 | 内容 |
| :--- | :--- |
| **广告** | OpenRTB、Header Bidding、App SDK、RTA、合规与归因 |
| **基建** | Netty、Kafka、Flink、Redis、高可用、Kubernetes |
| **模型** | 特征、召回 → 精排 → 重排、在线推理 |
| **Agent** | 循环、工具、记忆、评测、续跑，以及框架怎么对应这几层 |

每篇都自己画图，也会写清当时为什么这么选、放弃了什么。不写软文。
