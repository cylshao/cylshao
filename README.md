技术本身我是真喜欢，但广告这行更让我上心的，是它前面那截：谁在买、谁在卖、一次曝光怎么在几十毫秒里成交，钱又沿着哪条路分回去。工程只是这条因果链的中段，只盯着中段，很多决定会看不出道理。

我的日常是 DSP 竞价。一个 OpenRTB 请求进来，出价出去，中间卡着一个不讲情面的 `tmax`。往上是协议、拍卖规则、SDK 与合规，链路上是定向、频控、pacing 和打分，再往后是 Kafka、Flink 和在线推理。

哪一段还含糊，我就把它拆开写一遍，写到能跟人讲明白为止。判断自己有没有真懂，标准也简单：生意上的说法和延迟预算能不能对上，对不上就是还没懂。

## 最近在看：AI Agent

今年我把更多时间放在了 AI Agent 上。

有意思的地方不在模型聪不聪明。聊天能给你一份步骤，但一步都不会替你做；要真把事办完，它得自己调工具、把中间状态保住、在需要人点头的地方停下来，等人回了话再接着往下跑。

**对企业的价值。** 过去的自动化只覆盖规则清晰、量又大的那部分，剩下大量「说得清、却写不成规则」的活——查数、核对、整理材料、跨几个系统来回搬——始终得有人盯着。Agent 接的正是这一段：判断留给人，跑腿的部分交出去。落到我熟悉的广告业务上就很具体：运营不必再排队等取数，可以直接问竞品和投放数据；投放出现异常时，先由 Agent 把链路上的指标拉齐、给出初步判断，人再决定动不动手。省下的时间是次要的，更要紧的是把人从反复确认里挪开，放回真正需要判断的地方。

**未来的影响。** 我认为 Agent 最后不会是一个独立产品，而会成为业务系统里的一层，像今天的搜索和消息队列一样慢慢沉到底下。真正被改写的是分工：重复确认、跨系统搬运这类事会大量下沉给机器，人留在定义目标、划边界和担责任的位置上。门槛也会跟着挪，从「会不会用模型」变成「敢把系统交给它到什么程度」。

**我自己的判断。** 市场这一年已经从热闹回到务实。愿意先付钱的，基本都是边界清楚、结果可核对的场景：客服工单、代码与测试、线索整理、合规与文档审查、内部取数；越依赖隐性经验的环节，试点做得再漂亮也很难留下来。买方的问法同样变了，从「模型有多强」变成「这件事能不能稳定做完、错了谁负责、一个月多少钱」。所以我不太看重换哪个模型，能力上限更多取决于企业自己的数据、流程和权限梳理到什么程度——这恰恰是模型替不掉的部分。

**接下来。** 这个方向我会持续投入，未来两年主要做两件事：在广告业务里找那些边界清楚、值得交出去的环节真正落地；把过程中想清楚的和踩过的坑一并写下来。

## 在写什么

上面这些最后大都落成了文章。四个方向，问的其实是同一件事：流量怎么变成收入，系统在中间怎么跑。

| 方向 | 内容 |
| :--- | :--- |
| **广告** | OpenRTB、Header Bidding、App SDK、RTA、合规与归因 |
| **基建** | Netty、Kafka、Flink、Redis、高可用、Kubernetes |
| **模型** | 特征、召回 → 精排 → 重排、在线推理 |
| **Agent** | 循环、工具、记忆、评测、续跑，以及框架怎么对应这几层 |

每篇都自己画图，也会写清当时为什么这么选、放弃了什么。不写软文。
